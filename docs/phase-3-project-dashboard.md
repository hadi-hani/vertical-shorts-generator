# المرحلة 3 — تقرير: لوحة المشاريع (project-dashboard)

التاريخ: 2026-08-17
الفرع: `feature/project-dashboard` (من `saas`)

## ما أُنجز

- **`DELETE /api/jobs/:id`** — حذف مشروع يملكه المستخدم الحالي فقط (404 لغيره)،
  مع حذف ملفات المخرجات المقابلة (`.mp4`/`.srt`/`.ass`) من `OUTPUT_DIR`.
  أُضيف `projectsRepo.remove(id)`.
- **منع إعادة الإنشاء أثناء المعالجة**: في نهاية خط التوليد، إن حُذف المشروع
  أثناء المعالجة (لم يعد موجوداً أو تغيّرت حالته عن `processing`) تُتلف الملفات
  المنتَجة ولا يُعاد المشروع مكتملاً — لا ملفات يتيمة ولا صفوف زائدة.
- **صفحة `/projects`** (`public/projects.html` + `public/js/projects.js`):
  - تعرض **مشاريع المستخدم الحالي فقط** عبر `GET /api/jobs`.
  - العنوان = الفكرة إن وُجدت، وإلا مقتطف من النص (أول 70 حرفاً).
  - شارة الحالة بالعربية: قيد الانتظار / جارٍ التوليد / مكتمل / فشل / متقطع
    (وخطأ فشل المعالجة عندها).
  - أزرار تنزيل **MP4 وSRT وASS** للمشروع المكتمل، وزر **حذف** مع تأكيد.
  - **empty state عربي** "لا توجد مشاريع بعد…" مع رابط للأداة.
  - إعادة تحميل تلقائية كل 5 ثوانٍ ما دام هناك مشروع قيد المعالجة.
- **رابط "مشاريعي"** في شريط المصادقة (بجانب البريد وزر الخروج) للانتقال للوحة.
- حماية `app.js`: تجاهل الأداة إذا لم تُحمَّل (`window.SubtitlesTool`) حتى لا
  تنكسر صفحة اللوحة (لمس `subtitles.js` مطلقاً — خط أحمر).

## الاختبار

- **`npm run smoke` — 37/37 فحصاً نجحت** (أُضيفت فحوصات الحذف):
  - DELETE بدون مصادقة → 401.
  - المستخدم B لا يستطيع حذف مشروع A → 404.
  - A يحذف مشروعه → 200؛ ثم المشروع → 404 والملف → 404.
  - القائمة بعد الحذف تعرض مشروعاً واحداً.
  - وبقية فحوصات المراحل السابقة (29/31) ما زالت ناجحة.
- **فحص يدوي**: الخادم يعمل بالكود الجديد؛ `/projects.html` و`/js/projects.js`
  يُخدمان (200)؛ مشروع المستخدم الحقيقي ('الذكاء الاصطناعي') موجود في DB بحالة
  `completed` وسيظهر في اللوحة مع روابط التنزيل.

## ملاحظات
- لا إحصاءات ولا رسوم بيانية (كما طُلب).
- مسار الكابشن (`captions.js`/`subtitles.js`) لم يتغيّر.
- حذف مشروع قيد المعالجة يحذف الصف والملفات الحالية، والـ worker يتخلّى عن
  نتائجه عند الاكتمال (يُتلفها) — لا ملفات يتيمة.
