# المرحلة 1 — تقرير: ملكية المشاريع (user-projects)

التاريخ: 2026-08-17
الفرع: `feature/user-projects` (من `saas`)

## ما أُنجز

- ترحيل `002_projects.sql`: جدول `projects` يربط كل مشروع بـ `user_id` ويحفظ:
  النص (`idea`/`script`)، اللغة، النمط، وضع التوقيت، عدد الكلمات، الحالة،
  `error`/`error_code`، روابط MP4/SRT/ASS، `estimated_duration`، `meta` (JSON)،
  أوقات الإنشاء/التحديث/الاكتمال. مع فهرس `(user_id, created_at DESC)`.
- مخزن `app/db/repositories/projects.js` (CRUD + `toPublicProject`).
- `createJob` ينشئ سطراً في DB مع `req.user.id` (الحالة `queued`)، وكل انتقال
  حالة (processing/completed/failed) يُراد في DB عبر `updateJob`؛ يُضاف
  `completed_at` عند الاكتمال.
- العزل:
  - `GET /api/jobs` → مشاريع المستخدم الحالي فقط (من DB).
  - `GET /api/jobs/:id` → 404 إن لم يكن المشروع ملك المستخدم (لا يفضح الوجود).
  - `GET /api/outputs/:file` → استخراج `projectId` من اسم الملف والتحقق من
    الملكية قبل الإرسال؛ يمنع التخمين العشوائي والوصول المتقاطع للملفات.
- طابور الذاكرة والـ worker يبقيان كما هما مؤقتاً (المرحلة 2 تنقلهما إلى DB).

## الاختبار

- **`npm run smoke` — 29/29 فحصاً نجحت** (أُضيفت فحوصات عزل):
  - كل فحوصات المرحلتين السابقتين (401، تسجيل/دخول/خروج، النمطان، تنزيل).
  - المستخدم A يرى مشروعيه، المستخدم B لا يرى أي مشروع.
  - B لا يقرأ `/api/jobs/<idA>` (404) ولا يحمّل `/api/outputs/<idA>.mp4` (404).
  - A ما زال يقرأ مشروعه (200).
- **الثبات عبر إعادة التشغيل** (اختبار منفصل):
  - توليد مشروع → اكتمال → إعادة تشغيل الخادم بنفس DB → المشروع يظهر
    `completed` مع `outputUrl` (PERSIST OK).
- **مسار الكابشن**: لم يتغير (`captions.js` والأداتان)؛ النمطان أنتجا فيديوهات.

## ملاحظات
- أوامر التشغيل كما هي (`npm install && npm start` / `npm run smoke`).
- الفائدة الفورية: المشاريع المكتملة لا تضيع عند إعادة التشغيل (قبل المرحلة 2).
- المشاريع قيد المعالجة وقت إعادة التشغيل ستظهر عالقة `processing` مؤقتاً —
  المرحلة 2 (job-persistence) تعالجها بحالة `interrupted` وتنقل الـ worker إلى DB.
